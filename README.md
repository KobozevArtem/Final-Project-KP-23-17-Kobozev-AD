# Контейнер обеспечения безопасности приложения при угрозе заражения DNS-кеша

## Описание проекта

Проект представляет собой программный контейнер обеспечения безопасности приложения при угрозе заражения DNS-кеша. Контейнер предназначен для проверки сетевых соединений, анализа IP-адресов и URL, выявления небезопасных соединений, ведения журнала блокировок и мониторинга состояния приложения.

В рамках проекта реализовано Flask-приложение, которое генерирует тестовые сетевые соединения, проверяет IP-адреса и URL, отображает результаты проверки в веб-интерфейсе и позволяет оператору добавлять подозрительные IP и URL в журнал заблокированных соединений.

Проект развёртывается в контейнерной инфраструктуре Docker Compose и включает приложение безопасности, Nginx, PostgreSQL, pgAdmin, Prometheus и Grafana.

---

## Основные функции

Программный комплекс выполняет следующие функции:

* генерация тестовых IP-адресов разных типов;
* проверка корректности IP-адреса;
* проверка глобальности IP-адреса;
* проверка принадлежности IP-адреса доверенному списку;
* проверка URL и использования HTTPS;
* формирование решения о разрешении или блокировании соединения;
* отображение результатов проверки в веб-интерфейсе;
* построение диаграмм по результатам проверок;
* ведение журнала заблокированных IP и URL;
* сохранение журнала блокировок в `blocked_list.json`;
* экспорт метрик Prometheus;
* визуализация показателей в Grafana.

## Логика работы приложения

1. Пользователь открывает веб-интерфейс контейнера безопасности.
2. Приложение генерирует 10 тестовых соединений.
3. Для каждого соединения выбирается IP-адрес и URL.
4. Выполняется проверка IP-адреса:

   * корректность формата;
   * глобальность адреса;
   * принадлежность доверенному списку.
5. Выполняется проверка URL и HTTPS.
6. Формируется решение:

   * `True` — соединение разрешено;
   * `False` — соединение запрещено.
7. Результаты отображаются в таблице.
8. Пользователь может нажать кнопку «Заблокировать».
9. IP и URL сохраняются в файл `blocked_list.json`.
10. Prometheus собирает метрики приложения.
11. Grafana отображает показатели мониторинга.

## Журнал блокировок

Журнал заблокированных соединений хранится в файле:

```text
docker_k8s_lab/app/blocked_list.json
```

В журнал записываются:

* IP-адрес;
* URL;
* тип IP-адреса;
* причина блокировки;
* дата и время добавления.

Пример записи:

```json
{
    "ip": "192.168.1.1",
    "url": "https://bank.example.ru",
    "type": "Private_IP",
    "reason": "Соединение невозможно! IP-адрес не является глобальным",
    "blocked_at": "2026-06-07 12:30:00"
}
```

Журнал не сбрасывается при обновлении страницы, так как файл подключён к контейнеру через volume.

## Метрики Prometheus

В приложении реализована метрика:

```text
ip_checks_total
```

Она показывает количество выполненных проверок соединений с разделением по статусам:

```text
ip_checks_total{status="allowed"}
ip_checks_total{status="denied"}
```

Также доступны системные метрики Python-процесса:

* `process_cpu_seconds_total`;
* `process_resident_memory_bytes`;
* `process_virtual_memory_bytes`;
* `process_open_fds`;
* `python_gc_collections_total`.

Prometheus собирает метрики с адреса:

```text
security_app:8000
```
